which folder is Tomcat’s webapps folder

Tomcat’s webapps folder is inside your Tomcat install directory:

General: <TOMCAT_HOME>\webapps
Common Windows example: C:\Program Files\Apache Software Foundation\Tomcat 9.0\webapps
If you extracted a zip: C:\path\to\apache-tomcat-9.x.x\webapps
If you’re running Tomcat from an IDE (Eclipse/IntelliJ), it may use a separate “server base” folder, not the install directory.

explain what the dao do

DAO = Data Access Object. It’s the layer that talks to the database so your servlets don’t write SQL directly.

In this project:

UserDAO — find users by email/id, create new users (login/register).
ProductDAO — load products (with shop info), create/update products (admin).
VariantDAO — load product variants, create/update variants, decrement stock safely.
VoucherDAO — check if a voucher code is valid and active.
OrderDAO — create an order + order items in a transaction and reduce stock; if anything fails it rolls back.
ShopDAO — (added) load active shops.
So the DAO layer keeps database logic centralized, reusable, and easier to test.


the model ?

Model = the plain Java objects that represent your data (like tables/records).
They hold fields + getters/setters, no SQL.

In this project, models include:

User → user info (id, name, email, role…)
Product → product data (id, shopId, name, price…)
ProductVariant → size/color/stock
Voucher → discount code info
Order, OrderItem → order data
CartItem → items stored in session cart
Shop → shop info
So:
Model = data structure, DAO = database operations.


servelet ?

Servlet = the controller layer in Java Web.
It receives HTTP requests, runs logic/DAO calls, then forwards to a JSP view.

In this project:

LoginServlet / RegisterServlet / LogoutServlet → auth flow
ProductListServlet → load products and forward to products.jsp
CartServlet → add/update/remove cart items (session)
CheckoutServlet → apply voucher + create order
AdminProductServlet → admin CRUD for products/variants
HomeServlet → redirect (now mapped to /home)
So:
Servlet = request handler + control flow,
DAO = database access,
Model = data objects,
JSP = view/UI.

Hide products from customers without deleting data
Pause sales temporarily (out of stock, legal issue, seasonal)

what is price delta

Price delta is the extra price for a specific variant compared to the product’s base price.

Formula:

variant price = base_price + price_delta
Example:

Product base price = 100
Variant price = 120
→ price_delta = 20
So it lets you keep one base price for the product, and adjust variants up/down.

what are order and orderitem exactlly

Order = the main purchase record (one checkout).
It stores who bought, totals, status, time.

OrderItem = each line inside that order.
It stores which variant, quantity, and price.

Example:

Order #1001 (user 5) total = 120
OrderItems:
Variant 12, qty 2, unit 30
Variant 25, qty 1, unit 60

orderitems is the cart ?

Not exactly.

Cart = temporary items in the user’s session (before checkout).
OrderItems = saved items in the database after checkout.
So cart → checkout → order + order_items are created.

explain the code

OrderDAO is the data-access layer for creating orders:

Holds a VariantDAO to adjust stock.
Method createOrder(userId, total, discount, finalAmount, items):
Opens a DB connection and starts a transaction (setAutoCommit(false)).
Inserts a row into orders with totals and status PAID, then retrieves the generated order_id.
For each CartItem:
Calls variantDAO.decrementStock(...) to reduce inventory for that variant within the same transaction/connection.
Batches an insert into order_items with order_id, variant_id, quantity, unit_price.
Executes the batch, commits the transaction, and returns the new order_id.
On any error, rolls back and rethrows; finally restores autoCommit.
Key points:

Transactional: orders, order_items, and stock changes succeed or fail together.
Uses server-side generated keys to link order_items to the newly created order.
Status is hardcoded to "PAID" (no pending/unpaid state).

explain each paert of DAO

Here’s what each DAO does in your app:

UserDAO

findByEmail, findById — fetch a user.
create — insert a new user (used in register).
Maps fields: id, name, email, password_hash, role, created_at.
ProductDAO

findAll(includeInactive) — list products, joined with shop name/rating.
findById — one product with its shop info.
create, update — insert/update product (with shop_id).
findFeaturedByShopRating(limit) — top products ordered by shop rating.
searchByName(query) — search in name/description.
Maps product + shopName + shopRating.
VariantDAO

findByProduct, findById — get variants.
create, update — insert/update variant.
decrementStock(variantId, qty, conn) — atomically reduce stock (throws if insufficient).
VoucherDAO

findValidByCode(code) — returns an active voucher within date range.
OrderDAO

createOrder(userId, total, discount, finalAmount, items) — transactional: insert order, insert order_items batch, decrement variant stock, commit/rollback.
ShopDAO

findAllActive() — list active shops.
In short: DAOs = SQL layer. Models = data objects. Servlets = request handling. The DAOs keep DB logic isolated so servlets just call methods instead of writing SQL.
